FT-Transformer：将 Transformer 用于表格

先修：13 · 后续：15 公平比较

FT-Transformer 的关键设计是把数值和类别特征编码为 feature tokens，再用 Transformer 层建模特征间关系。

学习目标

  • 说明数值和类别特征如何形成 token。
  • 描述 Transformer 层在表格中的输入输出。
  • 概括原论文的比较结论及实验边界。
  • 识别计算成本和实现版本风险。

1. 特征 token 化

每个数值特征可以通过可学习的向量变换得到 token；类别特征通常先查 embedding。所有 token 组成一个序列，注意力层可以让面积参考城市、房龄参考收入等其他列。

2. 论文结论的边界

原论文比较了多种深度表格模型，报告 MLP 类基线仍然重要，并在其 benchmark 条件下展示 FT-Transformer 的竞争力；它还指出 Transformer 通常比 MLP 更慢。不能把这些条件化结果写成对所有树模型和所有数据集的绝对排名。

实现、依赖、调参和数据预处理都可能改变比较结果；正式课件必须绑定论文版本和实验协议。

4. 易错点

误区：每列 token 就等于自然语言词。正确理解：它们的语义和顺序假设不同。

误区：论文 benchmark 结果适用于所有数据。正确理解：必须绑定数据、预算和实现。

误区：Transformer 一定比 MLP 强。正确理解：模型成本和任务条件都重要。

5. 自测

FT-Transformer 的 token 通常对应什么？

通常对应输入特征或其编码表示。

类别列如何形成表示？

常见方式是查找可学习的类别 embedding。

为什么要记录实现版本？

API、默认参数和预处理行为可能变化。

原论文结论能否证明 GBDT 被淘汰？

不能；比较结论受 benchmark 和协议限制。

FT-Transformer 的额外成本是什么？

注意力计算、训练调参和推断资源通常高于简单 MLP，具体需实测。

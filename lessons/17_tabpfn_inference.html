TabPFN 的整体架构与推断流程

先修：13、16 · 后续：18 ICL

理解 TabPFN 的关键是分清两个时间点：预训练时更新参数，使用时把新数据集的训练样本和待预测样本输入固定模型。

学习目标

  • 画出预训练阶段与推断阶段。
  • 解释带标签上下文和测试特征的作用。
  • 区分固定参数与变化的上下文。
  • 对无法由论文确认的内部细节保持不确定标记。

1. 两阶段流程

预训练阶段从任务先验生成/采样任务，训练模型近似预测规则。
使用阶段输入新任务的带标签样本和待预测样本。
上下文当前任务中可供模型参考的训练样本与标签。
输出分类概率或回归预测，具体能力按 checkpoint/API 核验。

2. API 语义

当前官方仓库示例使用 TabPFNClassifier 或 TabPFNRegressor，调用 fit 传入训练数据，随后 predict 处理测试数据；fit 的语义是准备当前上下文，不应被简单等同为从随机初始化开始训练一个新模型。

from tabpfn import TabPFNClassifier; clf=TabPFNClassifier(); clf.fit(X_train,y_train); predictions=clf.predict(X_test)

API、默认版本和 checkpoint 下载行为必须按访问日期记录。

3. 易错点

误区：固定参数意味着预测不看训练数据。正确理解：训练数据标签正是上下文的重要部分。

误区：fit 一定意味着常规逐数据集参数训练。正确理解：对 PFN 使用需区分上下文装载和参数更新。

误区：论文没有描述的内部细节可以凭架构猜。正确理解：标记未核验。

4. 自测

预训练和使用阶段哪个更新固定参数？

预训练阶段更新；使用阶段按 PFN 范式固定参数进行上下文推断。

Xtrain 和 ytrain 的作用？

提供新任务的上下文样本和标签。

Xtest 是否提供标签？

预测时只提供待预测特征，标签是要估计的对象。

为何要记录 checkpoint？

不同 checkpoint 的任务能力、限制和许可可能不同。

遇到未确认的内部机制怎么办？

回到论文/官方资料，记录开放问题，不凭空补全。

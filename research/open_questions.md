# 开放问题与版本差异

## OQ-001：TabPFN 当前默认版本与历史版本的边界

- 现象：官方仓库当前默认 TabPFN-3.5，并提供 3.5-Fast、3、2.6、2.5 和 2 等版本化选择方式。
- 风险：把旧版“最多样本/特征”限制写成当前通用限制。
- 处理：课程第 20、21 节建立版本表，所有限制绑定版本和核验日期。
- 状态：部分解决；已在 2026-10-10 官方 Models 页面记录类别/特征/样本/模型可用性限制，硬件实测仍待完成。

## OQ-002：官方文档、论文和仓库的接口差异

- 现象：论文描述研究方法，官方仓库描述当前软件，二者不是同一层面的规范。
- 处理：论文只支撑方法事实；安装、参数和资源要求以当前官方文档为准，并记录访问日期。
- 状态：部分解决；已用官方仓库区分论文、安装、quick start、checkpoint 下载和当前 API，仍需在可运行环境核对实际版本与参数行为。

## OQ-003：TabPFN 的 ICL 术语边界

- 风险：直接套用语言模型 ICL 的机制或叙事。
- 处理：用“给定上下文样本进行预测”的操作定义，区分预训练参数、推断输入和微调。
- 状态：部分解决；PFN 原始论文与 TabPFN 原始论文已核对摘要层机制，课程已采用操作性定义；逐段论文核验仍待完成。

## OQ-004：树模型与深度模型的比较

- 风险：将特定 benchmark 上的结果推广为普遍规律。
- 处理：统一数据划分、调参预算、重复次数和资源记录，只报告条件化结论。
- 状态：初始协议已确定并在合成数据与一个 UCI 数据集上运行；跨数据集、预算公平性和统计区间仍待完成。

## OQ-005：当前 TabPFN 的解释、校准和不确定性能力

- 风险：把概率输出、置信度、校准和不确定性估计混为一谈。
- 处理：分别核对 API、论文和实际运行结果；未支持的能力明确写“未确认/不提供”。
- 状态：部分解决；官方仓库/Models 页面已确认接口、模型版本和许可边界，具体解释、校准和不确定性能力仍需逐项 API/实测核对。

## OQ-006：跨平台 GPU/CPU 资源要求

- 风险：README 中的建议会变化，且硬件表现依赖数据和版本。
- 处理：只记录核验时的官方建议；实测数据放入实验记录，不伪造通用性能。
- 状态：部分解决；官方仓库已记录 GPU 推荐与 CPU 5,000 样本提示，当前硬件时间、内存和 checkpoint 实测仍待完成。

## OQ-007：代码与模型权重许可证

- 现象：官方仓库代码与模型权重采用不同许可，部分权重为非商业许可。
- 影响：课件代码可复现与模型权重分发不是同一件事。
- 处理：README 和第 20/21 节分别记录代码许可、权重许可和下载/登录要求。
- 状态：部分解决；已按当前 Models 页面逐项记录代码 Apache 2.0 与模型权重非商业许可的分离，仍需在课件中逐版本绑定并保留后续快照。

## OQ-008：当前 Windows 工作站的 PyTorch DLL

- 现象：tabpfn 9.1.0 已安装；PyTorch 2.14.1、2.14.1+cpu 和 2.9.1+cpu 均在导入 c10.dll 时返回 WinError 1114。
- 影响：无法在本机完成 TabPFN checkpoint 下载、认证和预测验证。
- 已尝试：默认 PyTorch wheel、官方 CPU-only wheel、降低到 2.9.1+cpu。
- 处理：保留真实失败记录；不把 API 示例或官方文档当作本地运行通过。已检查 WSL/Docker 替代路径但当前工作站不可用，后续在新运行环境重试。
- 状态：当前工作站阻塞，未达到三次独立项目轮次的最终阻塞判定。
